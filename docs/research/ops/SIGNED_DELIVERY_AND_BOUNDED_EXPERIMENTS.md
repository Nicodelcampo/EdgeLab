# Signed local delivery and bounded future experiments

## Actual scope

Implemented on PR117: an offline authenticated closeout receiver, an explicit local canonical technical writer with destination deduplication and outbox acknowledgement, a structural experiment-charter gate, and serial single-process instrumentation. **Not a deployed Kaggle coordinator, approved production signer, remote latest witness, bound real Brain or 24/7 service.**

The frozen scientific engine and campaign were not modified or relaunched. No raw tick/tape data was downloaded or published by this change. The final MNQ09-26 audit was already preserved in research commit `eca53ec2277536b89f3b68cc39770c19dcba2483`. Five new focal and five new matrix exports are audited; validation, original-source certification and economics remain absent.

## Implemented interfaces

### 1. Authenticated receiver

`authenticated_closeout.receive_authenticated_closeout` consumes a detached Ed25519 acquisition receipt and pinned local bundle. A host-provisioned public-key registry binds each signer to `KAGGLE_CUSTODY`. There is no default key and no production signing function.

The receipt binds account, kernel ID, immutable version, execution/session ID, scope/contract, scientific commit, input/build identity, four independently reviewed bundle pins and a memory-measurement pin. The receiver verifies the exact externally expected identity, signed expiry, local bytes, terminal semantic state, census and timings via the existing MNQ projection. No candidate/rate/market text is projected into operational learning.

The current telemetry implementation supports **isolated Linux single-process high-water RSS**, including imports and allocations before instrumentation. Live or waited children invalidate this scope: their memory is never silently omitted. A multi-process driver needs a separately implemented whole-process-tree measurement, not `max(parent, child)` or summed high-water values. Sampled RSS, memory caps, local-host estimates and missing measurements cannot become a measured peak.

These signatures authenticate the configured custodian's assertion, not Kaggle itself or original export provenance. The custodian must independently verify complete/paginated outputs, execution/input/build binding, audit custody, measurement origin and source permissions **before signing**. No signatures were provisioned for historical MNQ jobs, and their missing RSS was not reconstructed or imputed.

### 2. Canonical technical writer and ack

`canonical_delivery.deliver_reviewed` requires a distinct signed `TECHNICAL_REVIEW`, exact draft/envelope/custody hashes, a host-bound proposer and destination ID, an ancestor anchor and an externally supplied current ledger tip. The host maps destination ID to the approved private path; receipt-provided paths are never used.

The writer uses existing `DurableHippocampus` methods. It records a deterministic operational episode, a closed typed technical step and a **PROPOSED/LOW** lesson. Text is fixed by code; no scientific outcomes, instructions or supplied narrative enter the operational episode. `outcomes_inspected=False` describes this target-free projection episode, not the original scientific MNQ analysis.

Destination IDs derive from provider/execution/version. Partial retry checks exact existing canonical payloads before appending missing records. The source audit receipt is a canonical dependency, so invalidation cascades to the lesson and blocks reuse. A `DELIVERED` outbox state means a historical technical acknowledgement, not current scientific eligibility or adoption; canonical invalidations remain authoritative.

Outbox transaction and cooperative destination delivery lock span append/ack. Canonical store locking additionally rejects stale concurrent views. If the process dies after canonical write but before ack, the outbox remains pending; after external latest-tip verification, retry deduplicates at destination and completes ack. Torn destination tails and conflicts are quarantined, not repaired by overwrite. This is local crash/retry idempotence, **not an exactly-once distributed service or two-host fencing guarantee**.

Outbox v1 snapshots remain readable. New `DELIVERED` events are validated/replayed; older code that does not understand them must not be used to restore a new snapshot. Repeated identical ingestion after delivery is a noop. Invalidated drafts remain blocked.

No real Brain ledger was modified. Production review keys, ledger mapping, witness/latest, revocation authority and operating host remain unbound. Trust roots generated by tests are fixtures only and must never be used in production.

### 3. Discriminating experiment charter

`experiment_charter.review_charter` requires a sealed matching knowledge context and a closed proposal: mechanism, primary estimand, controls, falsification, uncertainty/multiplicity plan, causal availability, dependency checks, prior-attempt pin and negative evidence references. Missing Brain/library or invalidated dependencies blocks the next design review. It does not treat an absent provider as empty knowledge.

The first slice is bounded to 1–3 distinct chronological **research** sessions strictly before 2026-10-01, causal full frozen formation history, at most 900 declared seconds and 4 GiB. Support declarations cannot drop below 100 resolved/origin and 80% active-session coverage. These are design bounds, **not runtime reservations, scientific validity or campaign permission**.

An unchanged repeat without explicit replication/new information is rejected. The information-per-cost ranking is an uncalibrated rubric; no numeric probability of edge or estimated information gain is invented. Allowed exploratory closeouts preserve negatives, low support, censoring, relative-only results and replication needs. No charter grants execution/holdout/promotion.

### 4. Profiling for the next technical shard

`stage_profile.StageProfiler` records serial preparation/JIT/detector/trigger/outcome/features/serialization/primary-analysis/export time and measured single-process RSS. It permits repeated substeps but rejects nesting, unknown stages, failure-as-success, post-fork reuse and children. It is instrumentation, not an executor, source-access gate or hostile-code sandbox. A trusted fixed driver must enforce wall/RSS caps and full-workload census.

`benchmarks/profile_instrumentation_demo.py` runs one fresh-process synthetic self-check with independent streaming parity. It is **not real-MNQ/full-engine parity or a baseline/candidate speed benchmark**.

Real longevity substep profiling remains next: one externally approved preholdout shard, exact source/selection/build/protocol pins, warmup preserved and outputs retained privately on Kaggle. No selection was invented, no benchmark winner was adopted and no change was installed in the frozen driver. After locating the dominant measured substep, implement **one** bounded batch/reuse candidate, compare all ordered outputs independently, then apply the existing benchmark screen and separate authorization.

## Proposed scientific question, not execution

Given the frozen-bank replication failures, a useful next design review is: **does the relative return difference persist after stricter exact-width and departure-side balance, with censoring and common-support losses retained?**

Keep the original event definitions and bank locked. Do not select new favorable thresholds from each contract. Predeclare the primary contrast and uncertainty/multiplicity procedure before any new outcomes; distinguish interval against mechanism, inconclusive interval, inadequate support and relative-only evidence. This is a proposed test of rival explanations, not proof that matching explains the pilot.

Data/session selection and a real canonical knowledge/negative-attempt export are not yet bound. No runnable scientific charter with fabricated hashes/dates is provided.
